🧠 什麼是 ReAct 模式？（Reasoning + Acting）

傳統的 Prompt Engineering 只要求模型「一次回答到底」，當面對複雜的多步驟任務（例如：查天氣、比價、寫程式並測試）時，模型極易在開頭就產生幻覺並一路錯到底。

2022 年 Yao 等人提出的 ReAct 模式，讓模型具備「思考（Thought）」與「行動（Action）」的交替循環：

  • Thought（思考）：在動手前，先進行內心獨白，拆解當前局勢。「我現在掌握了什麼？還缺少什麼資訊？」
  • Action（行動）：調用外部工具（如搜尋引擎、資料庫查詢、執行 Python 程式碼、閱讀檔案）。
  • Observation（觀察）：將工具執行的真實回傳結果餵回給模型，讓模型感知真實世界的反饋。
  • Next Thought / Finish：若資訊足夠則輸出最終解答，否則繼續進入下一輪 Thought！

📚 關鍵突破：Andrej Karpathy 的「LLM Wiki Pattern」

AI 大師 Andrej Karpathy 近期指出：現行的傳統 RAG 有著根本缺陷——知識無法複利累積（No Compounding Returns）。 每次提問時，系統重新抓取碎片、重新拼湊，用完即丟。

Karpathy 提倡的 LLM Wiki Pattern 提出全新視角：

  • 持久的維基資產（Persistent Compounding Artifact）：維護一個結構化的 Markdown 知識庫（包含 Papers、Concepts、Topics、Synthesis）。
  • LLM 作為專業知識庫維護者（Curator & Maintainer）：每當讀入新文獻，Agent 負責發散更新（Fan-out）相關頁面、建立雙向連結、標記學術爭端、維護索引與歷史紀錄。
  • 人機協同分工：人類負責挑選高價值素材與方向，Agent 負責繁重的格式整理與跨文獻整合。
⭐ 專案憲法（AGENTS.md / CLAUDE.md）的深層價值：
就像本講義庫一樣，當我們在專案根目錄建立完善的 AGENTS.md 時，任何新進的 AI Agent 都能第一時間理解本專案的目錄結構、配色原則、HTML 樣板與新增頁面 SOP。這正是從「單次隨性寫 Code（Vibe Coding）」走向「企業級可持續協作」的核心分水嶺！

🤔 隨堂思考題

問題 1：在多 Agent 協作（Multi-Agent）架構中，為什麼需要有 Coordinator（協調者）角色？

解答：當任務龐大時（如同時進行文獻檢索、代碼撰寫、單元測試、網頁部署），如果所有 Agent 各自行動容易發生死鎖、重複勞動或上下文衝突。Coordinator 負責維護全局任務清單（Backlog），將大任務切分成子目標分配給專責 Worker，並審查 Worker 回報的產出，確保整體方向與專案規範完全一致。

問題 2：為什麼本週作業強調建立 AGENTS.md 而不是單純把網頁做出來？

解答：因為單純做出一個網頁只是一次性的成果（One-off deliverable）；而建立一套具備規則、模板、SOP 的 AGENTS.md，代表你為這個專案建立了一套「數位憲法」。未來無論隔了多久、換成哪一款 AI，只要丟進這份指引，AI 就能以相同的品質標準與視覺風格，源源不絕地擴充新功能或新頁面，這才是現代 AI 工程化開發的核心競爭力！
