直覺理解 Self-Attention 與 Multi-Head 機制

💡 核心直覺：圖書館與 Q、K、V 檢索哲學

在過去的 RNN 與 LSTM 中，模型必須像人類「一個字接一個字讀小說」一樣，讀到句尾時往往早已忘記句首的主詞。 2017 年 Google 團隊在《Attention Is All You Need》中拋棄了循環結構，提出了 Self-Attention（自注意力機制）。

自注意力機制最生動的理解方式是「圖書館借書檢索比喻」：

🔍 Query (Q) - 檢索提問

當前詞彙想要打聽的事物。「我是 'it'，我想知道我代表誰？」

🏷️ Key (K) - 索引標籤

每個詞彙身上帶有的關鍵特徵標籤，用來與別人的 Query 比對相關度。

📦 Value (V) - 實質內容

一旦被選中，該詞彙所能貢獻給整體的具體語意向量與上下文資訊。

📐 核心計算公式：
Attention(Q, K, V) = softmax( (Q × Kᵀ) / √dₖ ) × V
第一步算出 Q 與各 K 的點積相似度，第二步除以 $\sqrt{d_k}$ 縮放避免極端梯度，第三步經由 Softmax 轉化為總和為 100% 的權重分配，最後加權混合 Value！

👥 為什麼需要「多頭（Multi-Head）」注意力？

單一組 Q、K、V 就像一個看事情角度單一的評委。多頭注意力（Multi-Head Attention）的做法是：將向量維度切割成 8 組或更高等分（例如 8 個 Heads），讓不同的 Head 各司其職：

  • Head 1：專門捕捉主詞與動詞的結構關係（語法視角）。
  • Head 2：專門捕捉代名詞（it, they）所指向的實體對象（指代消歧）。
  • Head 3：專門捕捉時間、地點等修飾副詞（語境視角）。

最後將所有 Head 的結果串接（Concatenate），並通過一個線性投影矩陣，完成最豐富的多角度語意融合。

💻 15 行 PyTorch 極簡核心實作

以下是使用 PyTorch 原生張量運算實現 Scaled Dot-Product Attention 的精簡寫法：

import torch
import torch.nn.functional as F

def scaled_dot_product_attention(Q, K, V, mask=None):
    # d_k 是 Key 向量的最後一個維度大小
    d_k = Q.size(-1)
    
    # 步驟 1: 計算 Q 與 K^T 的矩陣乘法，並除以 sqrt(d_k) 縮放
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
    
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)
        
    # 步驟 2: 通過 Softmax 將分數轉化為總和為 1 的機率分佈
    attention_weights = F.softmax(scores, dim=-1)
    
    # 步驟 3: 與 Value 向量進行矩陣加權混合
    output = torch.matmul(attention_weights, V)
    return output, attention_weights

🤔 隨堂思考題

問題 1：為什麼計算點積後一定要除以 √dₖ？不除會發生什麼事？

解答：當向量維度 $d_k$ 很大時（例如 64 或 128），向量點積的結果方差會變得非常大，導致某些分數特別高。 當這些極端分數送進 softmax 函數後，會被推擠到 Softmax 的兩端飽和區，其局部導數（梯度）幾乎趨近於零，這會造成梯度消失（Vanishing Gradient），導致神經網絡無法有效反向傳播學習！除以 $\sqrt{d_k}$ 能將方差拉回標準常態分佈，維持梯度順暢流動。

問題 2：Self-Attention 的計算複雜度是多少？在長文本（如 10 萬字）時會面臨什麼挑戰？

解答：若輸入長度為 $N$，每個 token 都要與其他 $N$ 個 token 進行點積計算，因此時間與空間複雜度皆為 $O(N^2)$ 二次平方級！ 當文本從 1,000 字增長到 100,000 字時，計算量會暴增 10,000 倍，導致 GPU 顯存迅速被 Attention 矩陣撐爆。這也是 FlashAttention、RoPE、Sliding Window 等長文本優化技術應運而生的主因。
